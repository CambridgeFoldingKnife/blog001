# 枚举类

有些变量的取值天生就是"有限的几个"：订单只有待支付、已支付、已取消；页面只有加载中、成功、失败。这种场景用枚举（`enum class`）表达，比用 `Int` 常量或者 `String` 清楚一百倍。

## 一、最基础的枚举

用 `enum class` 声明，常量之间用逗号分隔：

```kotlin
enum class Direction {
    NORTH, SOUTH, EAST, WEST
}

fun main() {
    val d = Direction.NORTH

    println(d)                          // NORTH
    println(d.name)                     // NORTH
    println(d.ordinal)                  // 0，声明顺序从 0 开始
    println(Direction.valueOf("SOUTH")) // SOUTH
}
```

每个枚举常量都是 `Direction` 的一个实例，天然单例、天然不可变，比字符串常量安全得多——你不可能把 `Direction.NORTH` 写成 `"NRTH"` 还编译通过。

## 二、带参数的枚举

枚举常量可以携带构造参数，非常适合"状态 + 附带信息"的场景：

```kotlin
enum class PageState(val code: Int, val desc: String) {
    LOADING(0, "加载中"),
    SUCCESS(200, "加载成功"),
    ERROR(500, "加载失败")
}

fun main() {
    println(PageState.SUCCESS.code)   // 200
    println(PageState.SUCCESS.desc)   // 加载成功
}
```

这样每个状态就带上了自己的附加数据，不用再写一堆 `when` 去映射编码。

## 三、枚举的方法与属性

枚举类里可以定义方法，每个常量也可以重写抽象方法：

```kotlin
enum class OrderStatus(val desc: String) {
    PENDING("待支付") {
        override fun canCancel(): Boolean = true
    },
    PAID("已支付") {
        override fun canCancel(): Boolean = false
    };

    abstract fun canCancel(): Boolean

    fun printInfo() {
        println("$name -> $desc，能否取消：${canCancel()}")
    }
}

fun main() {
    OrderStatus.PENDING.printInfo()
    OrderStatus.PAID.printInfo()
}
```

> **特别注意**
> 当枚举常量后面跟了额外成员（方法、属性、分号）时，**最后一个常量后面必须写分号**。漏了分号是新手最常见的编译错误之一。

### 3.1 每个常量不同的行为

上面 `PENDING` 和 `PAID` 分别实现了各自的 `canCancel()`，这就是"用枚举替代一大串 if-else"的经典写法。遍历时推荐用 `Direction.entries`，比老的 `values()` 更省内存。

## 四、when 配合枚举

`when` 和枚举是绝配：

```kotlin
fun describe(state: PageState): String = when (state) {
    PageState.LOADING -> "转圈中..."
    PageState.SUCCESS -> "展示内容"
    PageState.ERROR -> "展示重试按钮"
}
```

这里没有写 `else`，因为 `when` 作为表达式时，编译器会检查你是否覆盖了**所有**枚举常量。以后有人给 `PageState` 加了一个 `EMPTY`，这里会立刻编译报错，提醒你补分支。

用 `Int` 或 `String` 表示状态时，新增一个值编译器完全不知情，漏处理的分支要等运行时才暴露。用枚举 + `when`，漏分支在编译期就被抓住。

## 五、Android 中的实际用途

### 5.1 页面加载状态

```kotlin
var state: PageState by mutableStateOf(PageState.LOADING)

when (state) {
    PageState.LOADING -> LoadingView()
    PageState.SUCCESS -> QuestionList()
    PageState.ERROR -> ErrorView(onRetry = { load() })
}
```

这是 Compose 里最常见的写法：一个枚举描述当前页面处于哪个阶段，界面根据它切换。

### 5.2 题目作答状态

面试通的题目状态也可以具象化，例如 `enum class QuestionStatus { UNANSWERED, ANSWERED, WRONG }`，再配一个 `when` 把状态翻译成"未作答 / 已作答 / 答错了"。

### 5.3 枚举也能实现接口

```kotlin
interface Describable { fun describe(): String }

enum class Level(val score: Int) : Describable {
    LOW(1) { override fun describe() = "简单" },
    HIGH(3) { override fun describe() = "困难" };
}
```

## 六、枚举 vs 密封类

| 对比项 | enum class | sealed class |
| --- | --- | --- |
| 实例数量 | 编译期固定 | 子类固定，但子类可有多个实例 |
| 能否携带不同数据 | 所有常量共享同一组属性 | 每个子类可以有不同属性 |
| 典型场景 | 状态标识、类型标识 | 带数据的多态结果 |

比如"加载失败"如果要带错误信息 `Error(val msg: String)`，密封类更合适；如果只是区分 `LOADING / SUCCESS / ERROR` 这三个状态，枚举更轻、更直接。

## 七、小结

枚举的核心价值是"把有限取值收进一个类型里"。基础用法记住 `enum class`、`name`、`ordinal`、`entries`；进阶用法记住带构造参数、常量内重写抽象方法；实战重点是配合 `when` 做穷举检查。Android 里页面状态、订单状态、题目状态，基本都是枚举的主场。
