# 伴生对象

Java 里到处是 `static`：工具方法、常量、工厂方法。Kotlin 没有 `static` 这个关键字，取而代之的是 `companion object`。它做的是同一件事——让成员可以挂在类上，直接用类名访问。

## 一、从 Java 的 static 说起

先回忆一下 Java 的写法：

```java
public class Api {
    public static final String BASE_URL = "https://api.example.com";

    public static Api create() {
        return new Api();
    }
}
```

调用时直接 `Api.BASE_URL`、`Api.create()`，不需要创建对象。这些成员属于"类"而不是"某个实例"。Kotlin 里没有 `static`，同样的需求用伴生对象实现。

## 二、companion object 基本用法

`companion object` 写在类里面，本质上是"类内部的一个单例对象"：

```kotlin
class MathGameMini {
    companion object {
        const val MAX_LEVEL = 10

        fun calc(a: Int, b: Int): Int = a + b

        fun create(): MathGameMini = MathGameMini()
    }
}
```

几个要点：一个类**最多只能有一个** `companion object`；名字默认叫 `Companion`，可以自己起；里面的成员属于"类级别"，和实例无关；它本身是一个对象，所以也能声明 `val`、实现接口、继承类。

## 三、类名直接访问

这是伴生对象最爽的地方——调用时不用写 `.Companion`：

```kotlin
fun main() {
    val game = MathGameMini.create()
    println(MathGameMini.MAX_LEVEL)     // 10
    println(MathGameMini.calc(3, 4))    // 7
}
```

编译器会自动把 `MathGameMini.create()` 翻译成 `MathGameMini.Companion.create()`。你写 `MathGameMini.Companion.create()` 也能编译，但没人这么写；想让名字更表意也可以写 `companion object Net`，调用时就是 `HttpClient.Net.create()`。

## 四、和 Java static 的差异

| 对比项 | Java static | Kotlin companion object |
| --- | --- | --- |
| 本质 | 类上的静态成员 | 类里的一个单例对象 |
| 能否实现接口 | 不能 | 可以 |
| 能否继承类 | 不能 | 可以 |
| 调用写法 | `类名.成员` | `类名.成员`（语法糖） |
| 字节码 | `static` 方法 | 外部类持有 `Companion` 静态字段 |

### 4.1 实现接口的能力

这是伴生对象比 `static` 强的地方。因为它是对象，所以可以实现接口：

```kotlin
interface Factory<T> {
    fun create(): T
}

class QuestionItem private constructor(val title: String) {
    companion object : Factory<QuestionItem> {
        override fun create(): QuestionItem = QuestionItem("默认题目")
    }
}

fun main() {
    println(QuestionItem.create().title)   // 默认题目
}
```

`QuestionItem` 的构造函数是 `private`，外界只能通过伴生对象这个"工厂"来创建，这就是工厂模式的 Kotlin 写法。

### 4.2 和 Java 互操作

如果伴生对象的方法要被 Java 代码当静态方法调用，需要加 `@JvmStatic`，否则 Java 那边得写 `Api.Companion.ping()`，很别扭。只在需要 Java 调用时才加。

## 五、常见用途

### 5.1 工厂方法

```kotlin
data class User(val name: String, val age: Int) {
    companion object {
        fun fromJson(json: String): User {
            val name = json.substringAfter("\"name\":\"").substringBefore("\"")
            return User(name = name, age = 0)   // 简化示例
        }
    }
}

fun main() {
    println(User.fromJson("""{"name":"剑桥折刀"}""").name)   // 剑桥折刀
}
```

工厂方法让调用方不关心构造细节，`User.fromJson(...)` 可读性好太多。

### 5.2 常量：const val vs val

```kotlin
class Api {
    companion object {
        const val BASE_URL = "https://api.example.com"
        val TIMEOUT = 30_000
    }
}
```

这两个看起来像，区别却很大：

- `const val`：**编译期常量**，只能是 `String` 或基本类型，值在编译时确定，使用处会被**内联**成字面量；
- `val`：运行期初始化，可以有复杂计算，是普通的只读属性。

`const val` 还要求必须写在顶层、`object` 或 `companion object` 里，不能放在普通类体中。

> **特别注意**
> `const val` 的值会被内联到使用处，如果改了它的值，所有引用它的类都要重新编译才生效。频繁变动的常量建议用 `val`。

## 六、小结

`companion object` 是 Kotlin 对 Java `static` 的替代方案，成员可以像静态成员一样用类名访问。它比 `static` 更灵活，能实现接口、继承类；需要被 Java 调用时加 `@JvmStatic`。常见用途有三类：工厂方法、常量（`const val` / `val`）、类级别的私有工具字段。
