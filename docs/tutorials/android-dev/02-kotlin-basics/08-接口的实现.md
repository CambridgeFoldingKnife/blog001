# 接口的实现

上一篇讲继承，我们知道了 Kotlin 的类只能单继承。那如果一个类既想"会飞"又想"会游泳"怎么办？答案就是接口。接口只负责声明"你必须具备什么能力"，不关心你怎么实现。

## 一、接口是什么

接口用 `interface` 声明，抽象方法只写签名；实现类用冒号接接口名（**不带括号**，接口没有构造函数），方法必须 `override`：

```kotlin
interface Flyable {
    fun fly()
}

class Bird(val name: String) : Flyable {
    override fun fly() {
        println("$name 在飞")
    }
}

fun main() {
    Bird("小啾").fly()   // 小啾 在飞
}
```

## 二、一个类实现多个接口

这才是接口真正解决的问题：**能力组合**。一个类可以实现任意多个接口：

```kotlin
interface Flyable {
    fun fly()
}

interface Swimmable {
    fun swim()
}

class Duck(val name: String) : Flyable, Swimmable {
    override fun fly() {
        println("$name 拍打翅膀飞起来")
    }

    override fun swim() {
        println("$name 在水里游")
    }
}
```

### 2.1 继承 vs 接口

设计时记住一句话：**"是什么"用继承，"能做什么"用接口**。类只能单继承、有构造函数；接口可以多实现、没有构造函数，适合组合多种能力。

## 三、接口的默认方法

Kotlin 的接口可以有方法体，实现类不重写也能直接用：

```kotlin
interface Greetable {
    fun name(): String

    fun greet() {                       // 默认实现
        println("你好，我是 ${name()}")
    }
}

class Student(private val studentName: String) : Greetable {
    override fun name() = studentName
}

fun main() {
    Student("剑桥折刀").greet()   // 你好，我是剑桥折刀
}
```

如果两个接口都有同名同签名的默认方法，编译器会要求你显式指定用哪个，语法是 `super<接口名>.方法()`。

## 四、接口里的属性

接口可以声明属性，但**不能有 backing field**，所以不能直接赋值，只能声明或提供 `get()`：

```kotlin
interface Named {
    val name: String          // 抽象属性：实现类必须提供

    val displayName: String
        get() = "【$name】"     // 默认 getter，实现类可以不覆盖
}

class User(override val name: String) : Named

fun main() {
    println(User("剑桥折刀").displayName)   // 【剑桥折刀】
}
```

`override val name: String` 写在主构造里，就同时完成了"实现接口属性"和"声明类属性"两件事。

> **常见错误**
> 在接口里写 `val name: String = "abc"` 会编译失败，因为接口没有地方存这个字段。

## 五、Android 里的点击监听类比

接口在 Android 里最经典的应用就是各种 Listener：

```kotlin
interface OnItemClickListener {
    fun onItemClick(position: Int)
}

class QuestionAdapter(private val listener: OnItemClickListener) {
    fun click(position: Int) {
        listener.onItemClick(position)
    }
}

fun main() {
    val adapter = QuestionAdapter(object : OnItemClickListener {
        override fun onItemClick(position: Int) {
            println("你点了第 $position 题")
        }
    })
    adapter.click(2)   // 你点了第 2 题
}
```

`object : 接口名 { }` 创建的是匿名实现类。

### 5.1 单方法接口可以用 Lambda 简化

当一个接口只有一个抽象方法时（SAM 接口），Kotlin 允许直接用 Lambda 代替匿名对象，例如 `QuestionAdapter { position -> println("你点了第 $position 题") }`。

`QuestionAdapter { ... }` 里的 Lambda，就是 `OnItemClickListener` 的实现。Android 里 `setOnClickListener { }` 能这么写，靠的就是这个机制。

## 六、小结

接口的核心价值是"能力声明 + 多实现组合"：只告诉外界"我能做什么"，不暴露"我怎么做"。Kotlin 接口支持默认方法、支持属性（带 getter），一个类可以实现多个接口。Android 里的各种 Listener 就是接口最典型的落地场景，而单方法接口又能被 Lambda 进一步简化。
