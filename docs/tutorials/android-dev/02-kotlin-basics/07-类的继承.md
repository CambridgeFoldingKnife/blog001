# 类的继承

如果你是从 Java 过来的，第一次写 Kotlin 继承大概率会撞墙：明明 `class Dog : Animal()` 写得好好的，编译器却告诉你"这个类不能被继承"。原因很简单——Kotlin 的所有类默认都是 `final`。

## 一、Kotlin 的类默认是 final

在 Kotlin 里写 `class Animal`，等价于 Java 的 `public final class Animal {}`，**默认不可继承**。这是 Kotlin 有意为之：继承是最强的耦合，默认关闭能逼你多想一步——这个类真的需要被继承吗？而且 `final` 的方法可以被内联，调用更快。

## 二、open 与 override

想让类能被继承，必须加 `open`；方法默认也是 `final`，要重写同样要加 `open`：

```kotlin
open class Animal(val name: String) {
    open fun speak() {
        println("$name 发出了声音")
    }

    fun eat() {
        println("$name 在吃东西")
    }
}

class Dog(name: String) : Animal(name) {
    override fun speak() {
        println("$name 汪汪叫")
    }

    // override fun eat() {}   // 编译报错：eat 是 final 的
}
```

语法细节：子类继承用冒号 `:`，后面跟父类构造调用 `Animal(name)`；重写方法必须写 `override`。

> **常见错误**
> 只给类加了 `open`，忘了给方法加 `open`，子类 `override` 时会报 "is final and cannot be overridden"。类和方法的 `open` 是两回事，都要加。

## 三、子类必须调用父类构造函数

父类有主构造时，直接把参数透传上去：

```kotlin
open class Animal(val name: String, val legs: Int)

class Dog(name: String) : Animal(name, 4)
class Bird(name: String) : Animal(name, 2)
```

子类的 `name` 只是一个透传参数，没有声明为属性。如果父类没有主构造、只有次构造函数，子类就必须显式用 `super(...)` 调用：

```kotlin
open class Animal {
    var name: String

    constructor(name: String) {
        this.name = name
    }
}

class Dog : Animal {
    constructor(name: String) : super(name)
}
```

如果父类只有无参默认构造，子类写 `class Dog : Animal()` 即可。

## 四、super 调用父类方法

重写方法时，经常需要"保留父类行为，再补一点自己的"，用 `super.方法名()`。比如 `Dog` 重写 `speak()` 时先 `super.speak()` 再打印"汪汪叫"，输出就是两行。`super` 不是强制的，你完全可以只写子类自己的逻辑。

## 五、一个完整的"动物-狗"例子

```kotlin
open class Animal(val name: String, val legs: Int) {

    open fun speak() {
        println("$name 发出了声音")
    }

    open fun move() {
        println("$name 用 $legs 条腿移动")
    }

    fun sleep() {
        println("$name 睡着了")
    }
}

class Dog(name: String) : Animal(name, 4) {
    override fun speak() {
        println("$name 汪汪叫")
    }
}

class Bird(name: String) : Animal(name, 2) {
    override fun speak() {
        println("$name 叽叽喳喳")
    }

    override fun move() {
        super.move()
        println("$name 也可以飞")
    }
}

fun main() {
    val animals: List<Animal> = listOf(Dog("旺财"), Bird("小啾"))
    for (animal in animals) {
        animal.speak()
        animal.move()
        animal.sleep()
    }
}
```

这个例子体现了继承的两个核心价值：**多态**——`List<Animal>` 里可以放 `Dog` 和 `Bird`，调用 `speak()` 时各执行各的实现；**复用**——`sleep()` 只在父类写一次，子类直接继承。

### 5.1 重写后默认还是 open

子类 `override` 的方法默认仍然 `open`。不想再被孙类重写，就写成 `final override fun speak()`。

## 六、小结

Kotlin 继承记住四句话：类默认 `final`，要继承加 `open`；方法默认 `final`，要重写加 `open` + `override`；子类必须把父类构造调用上；想在父类行为之上扩展，用 `super.方法()`。把这四点记住，看框架源码就不会被 `open` / `override` 绕晕。
