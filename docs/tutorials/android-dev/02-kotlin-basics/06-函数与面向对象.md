# 函数与面向对象

这一篇信息量最大：函数定义、主构造函数、次构造函数、Java Bean 与 Kotlin Bean 的差异，以及类的初始化顺序。尤其是 `constructor` 什么时候写、什么时候能省，很多人到写项目都没搞明白。

## 一、普通函数定义

Kotlin 用 `fun` 声明函数，参数是"名字在前、类型在后"，返回值类型写在参数列表后面：

```kotlin
fun greet(name: String): String {
    return "你好，$name"
}

fun add(a: Int, b: Int) = a + b   // 单表达式函数，省略大括号和 return

fun main() {
    println(greet("剑桥折刀"))
    println(add(1, 2))
}
```

## 二、构造函数

### 2.1 最常用的主构造函数

主构造函数直接写在类名后面：

```kotlin
class Person(var name: String, var age: Int)

fun main() {
    val person = Person("剑桥折刀", 18)
    println("${person.name} 今年 ${person.age} 岁")
}
```

<img src="/images/android-dev/02-kotlin基础语法_06-函数与面向对象-2.png" alt="Kotlin 主构造函数写法" style="zoom:50%;" />

### 2.2 什么时候必须写 constructor

主构造默认可以省略 `constructor`，但主构造要加注解或可见性修饰符时必须写：

```kotlin
class Person @Inject constructor(var name: String)    // 依赖注入
class Student private constructor(var name: String)   // 只能内部创建
```

### 2.3 什么时候可以省

一句话：**主构造直接声明了 `var` / `val` 属性，且没有注解、没有可见性修饰符**，就可以省掉 `constructor`。这也是 99% 的场景；需要校验参数时放进 `init { require(age >= 0) }`。

`class Person constructor(name: String) { val upperName = name.uppercase() }` 这种写法里，`name` 没有 `var` / `val`，只是构造时用一下，所以 `constructor` 可写可不写。

## 三、次构造函数（了解即可，用得少）

次构造函数本质上就是 Java 里的**构造函数重载**：主构造无法满足多样化创建需求时，再加几个入口。

```kotlin
class Person(var name: String, var age: Int) {
    constructor(name: String) : this(name, 0)   // 只传名字时，年龄默认 0
}

fun main() {
    println(Person("小明").age)   // 0
}
```

> **特别注意**
> 次构造函数**必须委托给主构造函数**，写法是 `: this(...)`。因为 `var` / `val` 属性必须在主构造里完成初始化，次构造不能绕过。

## 四、Java Bean 和 Kotlin Bean 对比

Java 的标准 Bean 要有私有字段、构造函数、getter、setter，还要补 `equals` / `hashCode` / `toString`：

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // getter / setter / equals / hashCode / toString 还有几十行，省略
}
```

```kotlin
class Person(var name: String, var age: Int)
data class Person2(val name: String, val age: Int)   // 需要按内容比较时加 data
```

`data class` 更接近 Java 的 `record`，或者 Lombok 的 `@Data`。对应关系也很清晰：`var` ≈ `private 字段 + getter/setter`，`val` ≈ `private final 字段 + getter`。你在 Kotlin 里写 `person.name = "x"`，编译后调用的其实是 `setName("x")`。

## 五、类的初始化顺序

顺序是固定的：主构造参数初始化 → 类体属性初始化 → `init` 块 → 次构造函数体。

```kotlin
class Demo(val name: String) {
    private val greeting = "Hello, $name".also { println("2. 属性初始化") }

    init {
        println("3. init 块执行")
        require(name.isNotBlank()) { "name 不能为空" }
    }

    constructor(name: String, age: Int) : this(name) {
        println("4. 次构造函数体，age = $age")
    }
}

fun main() {
    println("1. 准备创建对象")
    Demo("剑桥折刀", 18)
}
```

输出顺序是 `1 → 2 → 3 → 4`。为什么这个顺序重要？因为**次构造函数委托给主构造的参数，同样会进入 `init` 代码块参与校验**。上面用 `Demo(name, age)` 创建对象，`init` 里的 `require` 一样执行了。不管你从哪个入口创建，初始化逻辑都不会漏，这正是 Kotlin 强制次构造委托主构造的原因。

## 六、小结

函数定义记三点：`fun` 开头、名字在前类型在后、单表达式可省大括号。构造函数记住口诀：主构造声明了 `var` / `val` 且无注解无修饰符，就不用写 `constructor`；有注解、有 `private`、或者参数只是临时用，就得写。次构造必须 `: this(...)`。至于 Java Bean 那一大坨，Kotlin 用 `class` 甚至 `data class` 就解决了。
