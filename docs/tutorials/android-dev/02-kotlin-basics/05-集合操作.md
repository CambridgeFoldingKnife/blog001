# 集合操作

Android 里几乎所有界面都在跟"一堆数据"打交道：轮播图、题目列表、聊天记录。Kotlin 的集合 API 极其顺手，这一篇我们把 `List`、`Map` 和高频操作符吃透。

## 一、List 集合

### 1.1 listOf：只读列表

`listOf()` 创建的是只读列表，不能增删，但能读、能遍历、能做各种转换：

```kotlin
fun main() {
    val numbers = listOf(1, 2, 3)
    println(numbers[0])       // 1
    println(numbers.size)     // 3
    // numbers.add(4)  // 编译报错，没有 add 方法
}
```

"只读"不等于"绝对不可变"，你只是拿不到修改的方法，所以可以放心把它当数据源往外传。

### 1.2 项目里的真实用法：首页轮播图

面试通首页的轮播图，就是把三张 banner 图放进一个 `listOf`：

```kotlin
private val banners = listOf(
    R.drawable.banner_ai,
    R.drawable.banner_pj,
    R.drawable.banner_qa
)
```

这类"配置型数据"天生不需要修改，用 `listOf` 最合适，界面里再按下标取资源 ID 展示。

### 1.3 mutableListOf：可变列表

需要动态增删时用 `mutableListOf()`，它支持 `add` / `remove`，例如 `mutableListOf("背单词").add("写代码")`。

### 1.4 题目列表为什么初始是 emptyList()

项目里的题目列表是这么定义的：

```kotlin
private val _questionList = MutableStateFlow<List<QuestionItem>>(emptyList())
val questionList: StateFlow<List<QuestionItem>> = _questionList.asStateFlow()
```

`emptyList()` 是只读空列表，作为初始值很合适。使用时不是 `add`，而是**整体替换**：

```kotlin
_questionList.value = _questionList.value + QuestionItem(1, "Kotlin 变量", false)
```

`List + 元素` 返回新列表，原列表不动。每次状态变化都是全新对象，界面才能准确判断"数据变了"。

> **特别注意**
> `MutableStateFlow` 判断"值有没有变"用的是 `equals`。直接对同一个 `MutableList` 调 `add`，引用没变，可能不触发刷新。正确姿势是创建新列表再赋值。

## 二、Map 集合

`Map` 是键值对集合，`mapOf` 创建只读 Map，`mutableMapOf` 可以增删改：

```kotlin
fun main() {
    val user = mapOf("name" to "剑桥折刀", "age" to 18)
    println(user["name"])                        // 剑桥折刀
    println(user.getOrDefault("email", "未填写"))  // 未填写
    println(user.containsKey("age"))             // true
}
```

遍历 Map 时可以用解构，直接写 `for ((key, value) in user)`，`key` 和 `value` 就分别是键和值。

## 三、集合操作符

这一组操作符是 Kotlin 的精华。共同点是：**不修改原集合，而是返回新集合**。

```kotlin
fun main() {
    val scores = listOf(78, 92, 55, 88, 100)
    println(scores.filter { it >= 60 })        // [78, 92, 88, 100]
    println(scores.map { it * 2 })             // [156, 184, 110, 176, 200]
    println(scores.sortedBy { it })            // [55, 78, 88, 92, 100]
    println(scores.any { it == 100 })          // true
    println(scores.all { it >= 60 })           // false
    println(scores.find { it < 60 })           // 55
}
```

容易混淆的点：`filter` 筛选并返回列表，`find` 找第一个并返回元素或 `null`；`any` 是"有没有一个满足"，`all` 是"是不是全都满足"；`map` 一对一转换，`flatMap` 一对多展开会拍平。对象集合排序时，`sortedBy` 接一个"取排序字段"的 Lambda，例如 `questions.sortedBy { it.difficulty }`。

## 四、集合的链式调用

操作符真正的威力在于"串起来"。真实场景：从题目列表里筛出**还没做过的题**，按难度排序，只要标题。

```kotlin
data class QuestionItem(
    val id: Int,
    val title: String,
    val done: Boolean,
    val difficulty: Int
)

fun main() {
    val questions = listOf(
        QuestionItem(1, "Kotlin 变量", true, 1),
        QuestionItem(2, "Kotlin 集合", false, 2),
        QuestionItem(3, "Kotlin 协程", false, 3),
        QuestionItem(4, "Java 基础", false, 1)
    )

    val result = questions
        .filter { !it.done }          // 1. 只留没做过的
        .sortedBy { it.difficulty }   // 2. 按难度从低到高
        .map { it.title }             // 3. 只要标题

    println(result)
    // [Java 基础, Kotlin 集合, Kotlin 协程]
}
```

这段代码读起来几乎就是自然语言：先过滤、再排序、最后映射。每一步都返回新集合，所以调整顺序、增删步骤都很安全。

> **常见错误**
> `filter` 之后忘记接收返回值，写成 `questions.filter { ... }` 单行放着不动。操作符不修改原集合，不接收返回值等于白写。

## 五、小结

`listOf` / `mapOf` 负责只读数据，`mutableListOf` / `mutableMapOf` 负责需要变动的场景。操作符记住四组就够日常开发：`filter`、`map`、`sortedBy`、`any/all/find`。链式调用把"筛选—排序—转换"变成一段可读性极高的代码，这也是 Kotlin 在 Android 里最好用的地方之一。
